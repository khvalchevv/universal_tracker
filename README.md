# universal-spread-tracker

Стежить за спредом між нативним активом на Binance і його обгорткою Universal
(uAsset) на Base. Коли розрив стає достатнім, щоб на ньому заробити — шле
сповіщення в Telegram.

Без залежностей: тільки стандартна бібліотека Python 3.9+.

## Що саме рахується

Universal мінтить нативний актив в обгортку **один-в-один, без комісій**, і сам
платить газ. Тому реальна можливість виглядає так:

```
купив SOL на Binance по ask
  -> замінтив у uSOL 1:1 безкоштовно
  -> продав uSOL за USDC на Base
```

Різниця за вирахуванням газу свопу — це `arb`, головне число трекера. Саме по
ньому спрацьовує алерт. Від'ємне значення означає зворотну можливість: обгортка
дешевша за оригінал, вигідно купити її та погасити 1:1.

Ціни на Base беруться **виконуваними квотами** агрегатора (KyberSwap) на
конкретний розмір угоди, а не серединою пулу — прослизання вже враховане.

### Обмеження

Квота агрегатора — це не симуляція транзакції. Враховано глибину пулів,
маршрут і газ; не враховано MEV, зміну стану до включення, твій баланс і
апрув. На дрібних розмірах два незалежні агрегатори збігаються в межах 0.02%,
на $5000 по XRP розходяться на 0.4% — тобто на величину самого еджу. Читай
цифри по XRP як оцінку, а не як факт.

## Пороги

Підібрані по 42–45 днях погодинної історії так, щоб алерт ловив реальні
дислокації, а не постійний шум.

| Актив | Поріг | Спрацьовує | Чому саме так |
|---|---|---|---|
| SOL | 0.8% | ~1.1 год/добу, 2.2 події/тиждень | медіана спреду близька до нуля, тіло розподілу вузьке |
| XRP | 1.2% | ~1.3 год/добу, рідкі довгі серії | медіана від'ємна, до 1% — шум навколо вартості кола; справжні дислокації глибокі й довгі |

Пул uXRP помітно гірший за глибиною, ніж uSOL, попри схожу заявлену
ліквідність: розрив між маркою пулу і реальною квотою — 0.6 п.п. проти 0.1 п.п.

## Розмір угоди має значення

`--size` визначає не тільки звіт, а й **що означає алерт**. Заміряна деградація:

| розмір | SOL arb | XRP arb |
|---|---|---|
| $1,000 | +0.46% | +0.68% |
| $5,000 | +0.44% | +0.41% |
| $10,000 | +0.40% | +0.16% |
| $25,000 | +0.31% | −0.44% |

SOL тримає до ~$25k, XRP видихається після ~$5k і виходить у нуль близько
$12k. Став `--size` рівним тому, чим справді торгуватимеш, інакше сповіщення
приходитимуть на едж, який не забереш.

## Запуск

```bash
export TG_BOT_TOKEN=...        # від @BotFather
export TG_CHAT_ID=...          # див. нижче
python3 spread_tracker.py
```

Підключення Telegram:

1. `@BotFather` → `/newbot` → токен
2. напиши своєму боту будь-що (без цього він не має права писати тобі)
3. `python3 spread_tracker.py --tg-setup` — покаже chat id
4. `python3 spread_tracker.py --tg-test` — перевірка доставки

### Ключі

```
--assets SOL,XRP     які активи стежити
--size 5000          розмір угоди в доларах
--threshold 0.5      єдиний поріг на всі активи (перекриває типові)
--interval 30        пауза між тіками, секунд
--csv spread_log.csv куди писати історію
--once               один замір і вихід
--webhook URL        POST JSON на алерті
--tg-cooldown 15     хвилин між повторами, поки спред тримається
```

## Команди бота

```
/status           пороги і останній замір
/set XRP 1.5      поріг для активу, у відсотках
/size 5000        розмір, на який рахувати квоти
/mute 60          тиша на N хвилин
/unmute
/help
```

Зміни зберігаються в `tracker_settings.json` і переживають перезапуск.
Пріоритет: ключ командного рядка > збережене з бота > типове для активу.

Бот приймає команди лише від `TG_CHAT_ID` — чужі ігноруються.

## Сповіщення

Спред тримається вище порогу годинами, тому сповіщення не сипляться на кожному
тіку:

- **вхід у зону** — одразу
- **поки тримається** — не частіше ніж раз на `--tg-cooldown` хвилин
- **вихід із зони** — одне підсумкове з піком за час вікна

## Ліміти API

При типових налаштуваннях (2 активи, тік 30 с):

| Сервіс | Використання | Ліміт | Запас |
|---|---|---|---|
| KyberSwap | 8 запитів/хв | 30 за 10 с (180/хв) | 95% |
| Binance | вага 8/хв | 6000/хв | 99.9% |
| Telegram | довге опитування | без обмежень для getUpdates | — |

Проксі та ротація IP не потрібні. Запас дозволяє опустити `--interval` до
~10 секунд або додати ще кілька активів.

## Дані

`spread_log.csv` — рядок на кожен замір: ціни обох сторін, обидві премії,
`arb`, газ, поріг і чи спрацював алерт. Придатний для подальшого аналізу
розподілу й перепідбору порогів.
